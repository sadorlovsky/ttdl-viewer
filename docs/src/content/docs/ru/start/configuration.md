У каждой настройки есть флаг и переменная окружения; флаг важнее.

| Флаг | Переменная | По умолчанию | Что делает |
|---|---|---|---|
| `--root <dir>` | `TTDL_VIEWER_ROOT` | запомненный | Каталог, где на каждый архив по подкаталогу |
| `--port <n>` | `TTDL_VIEWER_API_PORT` | `4174` | Порт, который слушает сервер |
| `--host <addr>` | `TTDL_VIEWER_HOST` | `127.0.0.1` | Интерфейс, к которому привязаться |
| `--lan` | — | выкл. | Привязаться ко всем интерфейсам — то же, что `--host 0.0.0.0`, названное по делу |
| `--likes <dir>` | `TTDL_VIEWER_LIKES` | найдётся | Экспорт TikTok, лежащий в стороне от архивов |

`--host` по умолчанию слушает петлю намеренно: этот процесс отдаёт произвольное локальное медиа без
всякой аутентификации перед собой и не должен оказаться в локальной сети случайно. Выход в сеть —
явный выбор: `--lan` — это он, и [образ Docker](/ru/guides/docker/) делает то же самое, потому что
внутри контейнера петля доступна только самому контейнеру, а открытость решается тем, какой порт вы
публикуете.

`--likes` — запасной выход, а не часть запуска. Даты сохранения обычно уже лежат в архиве: см.
[Даты лайков и избранного](/ru/guides/liked-dates/).

## Корень запоминается

`--root` — единственное, что он не может выяснить сам: ничто на машине не говорит, в какой каталог
качает ttdl. Поэтому он спрашивается один раз и сохраняется:

```bash
bun run start --root ~/code/ttdl/downloads   # запомнится на следующий раз
bun run start                                # и больше не понадобится
```

Ложится это в `~/.config/ttdl-viewer/config.json` (или в `$XDG_CONFIG_HOME`), где нет ничего, кроме
этой одной настройки. Это единственное, что программа пишет, и пишет она это вне всех архивов —
обещание состоит в том, что ничто здесь не может испортить загрузку, а не в том, что процесс никогда
не открывает файл на запись. Удалите файл, чтобы он забыл.

Сохраняется только корень, который вы действительно назвали; найденный перебором — нет, потому что
догадка, замороженная в настройку, продолжает отдавать не тот каталог и после того, как повод для
догадки исчез.

## Откуда он читает

Порядок разрешения:

1. `--root <dir>`
2. `TTDL_VIEWER_ROOT`
3. запомненный корень, если он сохранён
4. `./downloads`
5. `../ttdl/downloads`
6. `~/code/ttdl/downloads`
7. `./fixtures/downloads`

Явно заданный путь, которого нет, — это ошибка, а не повод провалиться в перебор: вы назвали
каталог, и его там нет. Если ничего из 4–7 тоже нет, сервер завершается и перечисляет всех
кандидатов, которых пробовал, потому что отсутствующий корень — обычная проблема первого запуска.

`./fixtures/downloads` стоит последним намеренно: там лежит синтетический архив, который создаёт
`bun run fixtures`, и рабочая копия с таким архивом иначе заслонила бы настоящие архивы
выдуманными постами — что читается как потеря данных, а не как не тот каталог.

Каждый непосредственный подкаталог корня — один архив. Каталог с файлом `.ttdl/.source` — это архив
**списка** (`downloads/liked/`): много авторов в одной плоской папке, и имя папки ничего не значит.
Всё остальное — архив **профиля**, где имя папки и есть хендл.

Каталог, в котором нет ничего из бухгалтерии ttdl — нет `.ttdl/`, — вообще не архив, и в библиотеку
он не попадает, а не появляется там профилем с нулём постов. Решается это через `stat`, а не через
перечисление: разница между «меньше миллисекунды» и 411 мс на тех архивах, против которых это
писалось.

До появления `.ttdl/` ttdl держал свою бухгалтерию плоско, рядом с видео, и переносит архив на
первой изменяющей команде, запущенной против него. Здесь читается только `.ttdl/` — см.
[чтение формата ttdl](/ru/reference/archive-format/), чтобы понять, как выглядит архив, этого
переноса ещё не переживший.
