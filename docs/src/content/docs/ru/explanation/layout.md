```

src/server/     Bun: скан → классификация → сборка → запрос, плюс корректная отдача по Range
src/web/        React: библиотека, сетка профиля, полноэкранная лента
scripts/        запускалка для разработки, генератор фикстур, офлайн-проверка
tests/          разбор имён файлов, паритет полноты с ttdl, матрица Range
docs/           этот сайт
```

## Общая середина

В `src/shared/filters.ts` лежит одна реализация строки запроса, которой пользуются и маршрут
сервера, и состояние URL в приложении. Именно эта общность не даёт разъехаться
[контракту API](/ru/reference/http-api/) и ссылке «поделиться этим видом» — а заодно означает, что
`serializeQuery(q)` служит и ключом кеша React Query, из-за чего открытие ленты из плитки сетки
переиспользует уже загруженные страницы вместо повторного запроса.

Этот сериализатор намеренно выбрасывает курсор: строка идентифицирует *вид*, а курсор — позицию
внутри него. Включить его значило бы дать каждой странице бесконечной прокрутки свой ключ кеша при
одном и том же фильтре.

## Разделение на сервере

Сервер держит две вещи порознь намеренно. **Объекты постов** — это то, что отдаёт JSON API;
**карта групп файлов от сканера** — это то, что превращает URL в имя файла, и единственное, что
этим вообще занимается.

Ни одна строка из запроса нигде не склеивается в путь. Идентификатор архива индексирует закрытую
карту, построенную сканером, идентификатор поста индексирует карту групп этого архива, а имя файла
читается из группы — так что попытка обхода каталогов упирается в отсутствующий ключ карты, а не в
родительский каталог.
