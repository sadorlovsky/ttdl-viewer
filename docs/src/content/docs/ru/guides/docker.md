description: Образ из Bun плюс пары сотен килобайт, монтирование только на чтение и порт, опубликованный на петлю.
---

В рантайм-образе нет `node_modules` вообще: сервер импортирует только встроенные модули `node:` и
собственные файлы, а React и всё прочее уже собрано в `dist` на этапе сборки. Так что образ — это
Bun плюс пара сотен килобайт приложения.

```bash
docker compose up -d --build
```

Дальше откройте <http://127.0.0.1:4174> на хосте.

Навести его на ваши архивы можно переменной `TTDL_ARCHIVES` — слева в томе каталог, в который пишет
ttdl, справа должно остаться `/archives`:

```bash
TTDL_ARCHIVES=$HOME/code/ttdl/downloads docker compose up -d --build
```

Или без compose:

```bash
docker build -t ttdl-viewer .
docker run -d --name ttdl-viewer \
  -v "$HOME/code/ttdl/downloads:/archives:ro" \
  -p 127.0.0.1:4174:4174 \
  ttdl-viewer
```

Две вещи в этой команде намеренны:

- **`:ro`.** Просмотрщик по устройству не пишет в архив; монтирование только на чтение заставляет
  ядро это соблюдать, так что никакая ошибка здесь не тронет загрузку.
- **`127.0.0.1:4174:4174`.** Порт публикуется только на хост. Возьмите `-p 4174:4174`, чтобы
  дотянуться с других машин в сети, — но логина перед ним нет, так что делайте это только в сети,
  которой доверяете.

## Опубликованный образ

Каждый тег собирается под `linux/amd64` и `linux/arm64` и уходит в GitHub Packages, так что NAS или
Pi ничего не собирает у себя:

```bash
docker pull ghcr.io/sadorlovsky/ttdl-viewer:0.1.0
```

| Тег | Что это |
|---|---|
| `0.1.0` | Один релиз. Единственный тег, который никогда не двигается |
| `0.1` | Самый свежий патч этой минорной версии |
| `latest` | Самый свежий релиз, кроме предрелизов |
| `edge` | Текущий `main`, пересобирается на каждый пуш |
| `sha-<коммит>` | Один коммит в `main` |

`edge` проходит те же проверки, что и релиз: воркфлоу, который его пушит, сначала гоняет тесты,
проверку типов, линтер и офлайн-гард. Больше про него ничего не сказано, поэтому на машине, которая
не должна меняться сама по себе, закрепляйте точную версию.

В `docker-compose.yml` закомментируйте `build` и раскомментируйте `image`:

```yaml
services:
  ttdl-viewer:
    # build: .
    image: ghcr.io/sadorlovsky/ttdl-viewer:0.1.0
```

Дальше `docker compose up -d` без `--build`, а `docker compose pull` переводит на более свежий тег.

## Как подхватить новые посты

Индекс строится в памяти при старте, кеша на диске нет, поэтому **перезапустите контейнер после
того, как ttdl скачает новые посты** (`docker restart ttdl-viewer`) или воспользуйтесь эндпоинтом
пересканирования:

```bash
curl -X POST http://127.0.0.1:4174/api/archives/<archive>/rescan
```

Что он сообщает в ответ — см.
[`POST /api/archives/:archiveId/rescan`](/ru/reference/http-api/#post-apiarchivesarchiveidrescan).

:::caution
Инструкции для Docker и Synology не запускались — они написаны по Dockerfile и по документированному
поведению DSM. См. [Известные ограничения](/ru/explanation/known-limits/).
:::
