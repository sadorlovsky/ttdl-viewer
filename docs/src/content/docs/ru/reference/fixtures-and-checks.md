## Фикстуры

Настоящего архива ttdl во время разработки не было, так что генератор — это то, чем код вообще
проверяется. Ему нужен `ffmpeg` (`brew install ffmpeg`), и он детерминирован от `--seed`.

```bash
bun run fixtures
```

Он пишет `fixtures/downloads/`: архив профиля, список с многими авторами, пустой архив, каталог
посторонних файлов и экспорт данных TikTok. Состояние уровня архива — карточка и картинка,
счётчики, `.source`, сайдкар с громкостью — попадает в `.ttdl/` каждого архива, где его держит ttdl
и откуда его читает индексатор.

В архиве профиля намеренно собран каждый крайний случай, который формат может выдать:

- даты `NA` и посты вообще без метаданных
- пост без обложки и обложка карусели в `.jpeg`
- `expected: 8` при пяти изображениях на диске
- файл состояния без счётчика
- изображение нулевой длины и осиротевший `.info.json`
- подпись с 15-значным числом
- карусель, у которой аудио и изображения несут разные даты
- видео 4:3 и 1:1
- карусели и в `.m4a`, и в `.mp3`

Каждому созданному файлу mtime ставится равным времени публикации его поста, повторяя `set_times` у
ttdl. Без этого всё, что рассуждает про mtime, проверялось бы в условиях, которых не бывает.

```bash
bun run fixtures --big
```

Добавляет 4000 постов через клоны APFS с копированием при записи — около 174 МБ настоящего диска,
хотя `du` показывает 16 ГБ, потому что общих блоков он не видит.

## Проверки

```bash
bun test           # разбор имён файлов, паритет с ttdl, матрица Range
bun run typecheck
bun run lint
bun run build      # сборка vite, затем офлайн-проверка по dist/
```

`scripts/check-offline.ts` роняет сборку на любой удалённой ссылке в бандле. Его белый список
держат узким — конкретные пути, никогда не хосты целиком, — потому что запись на весь хост
пропустила бы и то, что этот хост начнёт отдавать потом.

## Документация

Сайт, который вы читаете, — отдельный проект на Astro в `docs/`, со своими зависимостями:

```bash
cd docs
bun install
bun run dev        # http://localhost:4321
bun run build      # docs/dist
```

Это Cloudflare Worker, отдающий статику, — скрипта воркера нет, только каталог, который выпускает
`astro build`, описанный в `docs/wrangler.jsonc`. Cloudflare собирает и выкладывает его на каждом
пуше в `main`, затрагивающем `docs/`, через привязку репозитория в Workers Builds.

Выложить руками из `docs/` — те же два шага, что делает CI:

```bash
bun run deploy
```

Собственный домен указан в `wrangler.jsonc` маршрутом, а не в панели, так что DNS-запись и
сертификат следуют из выкладки, а не остаются шагом, который кто-то должен помнить.

Одну настройку так в репозиторий перенести не вышло. В образе сборки Cloudflare едет Bun 1.2.15,
который не умеет читать `lockfileVersion: 2`, пишущийся Bun 1.4: он игнорирует `bun.lock` и затем
падает на `--frozen-lockfile`, что с его стороны правильно. Свою версию Bun берёт только из
переменной сборки `BUN_VERSION`; в отличие от Node, Python и Ruby, файла с версией у него нет. Так
что настройки сборки несут `BUN_VERSION = 1.4.0`, записанный здесь потому, что в репозитории его не
фиксирует ничто.

Пути наблюдения для сборки — `docs/*`, считаемые от корня репозитория, а не от корневого каталога
проекта, так что коммит, трогающий только просмотрщик, сайт не пересобирает.
