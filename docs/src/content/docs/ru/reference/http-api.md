---
title: HTTP API
description: JSON, на котором работает приложение, — архивы, посты с пагинацией по ключу и корректная отдача по Range.
---

Всё, что знает интерфейс, он знает из этих маршрутов. Они без аутентификации и только на чтение, с
одним исключением (`rescan`), которое перечитывает каталог и ничего не пишет.

Базовый URL — собственный адрес сервера, по умолчанию `http://127.0.0.1:4174`. В `bun run dev`
сервер Vite на `:4173` проксирует `/api` и `/media` к нему, так что одни и те же пути работают с
любого порта.

`:archiveId` — это `encodeURIComponent(<имя каталога>)`. `:postId` — идентификатор поста, который
захватил ttdl: десятичная строка не короче 15 цифр.

## Ошибки

Каждый JSON-маршрут падает в одной и той же форме, и некоторые отказы несут команду, которая их
чинит:

```json
{
  "error": {
    "code": "POST_NOT_FOUND",
    "message": "This post has no .info.json",
    "hint": "Backfill it with: ttdl.py meta lowtide"
  }
}
```

| Код | Статус | Когда |
|---|---|---|
| `ARCHIVE_NOT_FOUND` | 404 | Архива с таким идентификатором нет, или его каталог больше не читается |
| `POST_NOT_FOUND` | 404 | Такого поста в архиве нет, или его метаданные пропали |
| `MEDIA_NOT_FOUND` | 404 | У поста нет файла такого рода, или его больше нет на диске |
| `NOT_FOUND` | 404 | Нет маршрута, или отсутствует ресурс |
| `INTERNAL` | 500 | Всё необработанное |

Все JSON-ответы идут с `Cache-Control: no-store`. Индекс — снимок каталога, в который другая
программа ещё пишет, так что кешировать его значит отдавать пост, удалённый десять минут назад.

## Архивы

### `GET /api/stats`

Используемый корень, каталог экспорта, если он нашёлся, и итоги по всем архивам.

```json
{
  "root": "/Users/you/code/ttdl/downloads",
  "likesDir": null,
  "archives": 4,
  "posts": 4091,
  "bytes": 214748364800,
  "builtAt": 1755000000,
  "version": "0.1.0"
}
```

### `GET /api/archives`

Все архивы, найденные под корнем.

`authors` возвращается здесь **пустым** намеренно: архив списка может нести их тысячами, а сетка
библиотеки всё равно читает только `authorCount`. Полный массив стоит своих байтов на странице
одного архива, а не в перечислении всех.

### `GET /api/archives/:archiveId`

Один архив, с заполненным `authors` — отсортированным по числу постов, по убыванию.

Заметные поля:

| Поле | Что значит |
|---|---|
| `kind` | `profile` или `list`. Файл `.ttdl/.source` делает архив списком |
| `counts` | `posts`, `videos`, `carousels`, `incomplete`, `ghosts`, `withoutInfo`, плюс собственные `archived` / `known` / `missing` от ttdl |
| `card` | `.ttdl/profile.json` от ttdl, с датой `fetchedAt`, когда его сняли. У архива списка не бывает никогда |
| `primaryAuthor` | Единственный автор архива профиля; крупнейший — у списка |
| `dateRange` | `{ first, last }` в секундах Unix, либо null |
| `downloadInProgress` | Пока ttdl работает, он держит `.ttdl/.lock` — интерфейс показывает баннер |
| `scannedAt` | Когда эта запись индекса была построена |

`counts.ghosts` — посты с метаданными или обложкой, но без медиафайла: что-то, что удалили с диска.
`counts.incomplete` — карусели, у которых аудио на месте, а изображения не все; см.
[Чтение формата ttdl](/ru/reference/archive-format/).

### `POST /api/archives/:archiveId/rescan`

Перечитывает каталог и перестраивает индекс этого архива. Так новые посты появляются без
перезапуска сервера.

```json
{ "changed": true, "counts": { "posts": 4093, "…": 0 }, "tookMs": 214 }
```

`changed` сравнивает хеш листинга сканера до и после, так что пересканирование, ничего не нашедшее,
об этом и говорит, а не сообщает о расплывчатом успехе. Архив, чей каталог стал нечитаемым,
возвращает `ARCHIVE_NOT_FOUND`, а не успешное пересканирование, ничего не изменившее.

## Посты

### `GET /api/archives/:archiveId/posts`

Отфильтрованный, упорядоченный вид с пагинацией по ключу. Это единственный маршрут с настоящей
строкой запроса, и она [разбирается кодом, общим с приложением](/ru/explanation/layout/) — контракт
API и ссылка «поделиться этим видом» разъехаться не могут.

| Параметр | Значения | По умолчанию |
|---|---|---|
| `q` | Подстрока по описанию, заголовку, хендлу и имени автора, треку и исполнителям | — |
| `author` | Хендл, повторяемый. `-` значит «автор не записан» | — |
| `hashtag` | Повторяемый; `#` снимается, приводится к нижнему регистру. Совпасть должны **все** | — |
| `kind` | `video` \| `carousel` | оба |
| `status` | `complete` \| `incomplete` \| `all` | `complete` |
| `from` / `to` | `YYYY-MM-DD`, включительно, UTC | — |
| `minDuration` / `maxDuration` | Секунды | — |
| `sort` | `date` `likes` `views` `comments` `saves` `duration` `liked` `random` | `date` |
| `order` | `asc` \| `desc` | `desc` |
| `seed` | Любая строка; только вместе с `sort=random` | `0` |
| `limit` | 1–200 | 30 |
| `cursor` | Непрозрачный, с предыдущей страницы | — |

Всё неопознанное игнорируется, а не отвергается: неизвестный `sort` откатывается к `date`,
некорректный `from` отбрасывается. `limit` зажимается, а не отклоняется.

```json
{ "items": [ /* Post */ ], "total": 3307, "cursor": "NzY3MzQ1…" }
```

`total` — размер отфильтрованного вида, а не страницы. `cursor` в конце равен null.

#### Курсор это ключ, а не смещение

Это base64url идентификатора последнего поста, и следующая страница продолжается *после* него. ttdl
и этот просмотрщик регулярно работают одновременно, а пересканирование, случившееся посреди
прокрутки, сдвигает все смещения после точки вставки — что проявляется как задвоенные и пропущенные
посты в бесконечной ленте. Продолжение от идентификатора к этому невосприимчиво.

Если поста из курсора к моменту запроса уже нет — ttdl удалил или переименовал его между
страницами, — последовательность **заканчивается**: `{ items: [], cursor: null }`. Начать сначала
значило бы дописать первую страницу в бесконечную ленту, задвоив ключи и вернув ровно тот же курсор,
так что клиент запрашивал бы его вечно.

#### Порядок полон, а null уходят в конец

Посты без значения по выбранному ключу уходят в конец при **любом** направлении: архив без
метаданных не должен всплывать наверх списка «самых лайкнутых». Ничьи разрешаются по `createdAt`,
затем по идентификатору поста численно (сначала по длине: 15-значный идентификатор, начинающийся с
9, меньше 19-значного, начинающегося с 1). Курсору по ключу нужна именно эта полнота: порядок
обязан быть устойчивым, а не просто выглядеть согласованным.

`sort=random` — перемешивание по сиду (xmur3 + mulberry32), так что порядок переживает перезагрузку
страницы.

### `GET /api/archives/:archiveId/posts/:postId`

Один объект `Post`, той же формы, что элемент страницы выше. Ключевые поля:

| Поле | Что значит |
|---|---|
| `kind` / `status` | `video` \| `carousel`; `complete` \| `incomplete` |
| `createdAt` / `createdAtSource` | Секунды Unix, есть всегда. Источник — `info`, `filename` или `postid`, чтобы интерфейс мог пометить выведенную дату как выведенную |
| `media` | `{ url, kind, ext, bytes, width, height, fps, aspectRatio }` |
| `photos` | Только для карусели: `count` на диске, `expected` из `_photo.json` (null у старой карусели) и `urls` |
| `stats` | `views`, `likes`, `comments`, `shares`, `saves` — любое из них может быть null |
| `loudnessGain` | Децибелы, из `loudness.json` от ttdl. Null значит *этот пост не измеряли*, а это другой факт, чем измеренный `0.0` |
| `liked` | `{ at, kind: "like" \| "favorite" }` либо null — см. [Даты лайков и избранного](/ru/guides/liked-dates/) |
| `webpageUrl` | Показывается и копируется; никогда не рисуется живой ссылкой |
| `hasInfo` | Есть ли `.info.json` — именно это нужно маршруту ниже |

Каждый `null` в счётчиках значит «не записано», а не «ноль». Интерфейс рисует такие как `—`.

### `GET /api/archives/:archiveId/posts/:postId/info`

Отдаёт `.info.json` от ttdl **дословно**, прямо с диска — это запасной выход для всего, что форма
`Post` выбрасывает. Отвечает 404 с подсказкой `ttdl.py meta <archive>`, когда файла метаданных у
поста нет.

Учтите, что сам индексатор выбрасывает `formats[]` и `thumbnails[]`, вычитав из них геометрию: они
полны живых подписанных ссылок на CDN. Этот маршрут отдаёт сырой файл, так что дальше вы с ними сами
по себе.

### `GET /api/archives/:archiveId/posts/:postId/neighbors`

Позиция поста внутри отфильтрованного вида плюс его соседи — строка запроса та же, что у `/posts`.
Именно это заставляет работать глубокую ссылку в ленту без перелистывания до неё.

```json
{ "prev": "7673…", "next": "7674…", "position": 41, "total": 3307 }
```

`position` равна `-1`, когда поста в этом виде нет вовсе.

## Выбор значений

### `GET /api/archives/:archiveId/authors`

`?q=` ранжирует нечётко, `?limit=` до 200 (по умолчанию 50). Без `q` — авторы архива в порядке
числа постов.

Нечёткое сопоставление живёт здесь, а не поверх описаний, потому что авторов не больше нескольких
сотен, а хендл в TikTok никто не помнит точно.

### `GET /api/archives/:archiveId/hashtags`

`[{ tag, count }]`, ранжируется по количеству, затем по алфавиту. `?q=` ранжирует нечётко, `?limit=`
до 500 (по умолчанию 50).

## Медиа

| Маршрут | Что отдаёт |
|---|---|
| `GET /media/:archiveId/avatar` | `.ttdl/avatar.jpg` архива, когда ttdl её записал |
| `GET /media/:archiveId/:postId/media` | Видео или звуковую дорожку карусели |
| `GET /media/:archiveId/:postId/cover` | Изображение обложки |
| `GET /media/:archiveId/:postId/photo/:index` | Одно изображение карусели |

`HEAD` работает на всех четырёх.

### Ни одна строка запроса не становится путём

Это единственное место, где запрос превращается в файл, и делает он это без склейки:
идентификатор архива индексирует закрытую карту, построенную сканером, идентификатор поста
индексирует карту групп этого архива, а имя файла читается из группы. Попытка обхода каталогов
упирается в отсутствующий ключ карты, а не в родительский каталог.

### Range и кеширование

`Accept-Ranges: bytes` на всём. Обрабатываются все три законные формы, потому что каждая приходит от
настоящего клиента:

| Заголовок | Что значит |
|---|---|
| `bytes=0-499` | Обычный кусок |
| `bytes=500-` | Открытый — то, что шлёт Safari после своей первой пробы |
| `bytes=-500` | Суффикс; некоторые реализации перемотки спрашивают так |

Множественный Range (`bytes=0-99,200-299`) получает в ответ `200` и файл целиком. Это законно по
спецификации и куда проще, чем собирать `multipart/byteranges`, а ни одному медиаэлементу он не
нужен. Невыполнимый Range получает `416` с `Content-Range: bytes */<size>`.

**Открытые диапазоны зажимаются до 8 МиБ**, но только для медиа со временем. Chrome просто
спрашивает следующий кусок, и память остаётся ровной, вместо того чтобы один `bytes=0-` на большом
видео держал целый ответ. Изображение всегда дешевле отдать целиком, чем заставить браузер спросить
дважды, поэтому оно не зажимается.

`ETag` — это `"<размер в hex>-<mtime в hex>"`, а `If-None-Match` получает `304`. Медиа отдаётся с
`public, max-age=31536000, immutable` — это безопасно, потому что URL несёт `?v=<mtime>`, так что
изменившийся файл есть изменившийся URL.

## Всё остальное

В продакшене тот же процесс отдаёт собранное приложение. Любой путь, которому не соответствует
настоящий файл в `dist/`, возвращается как `index.html`, потому что клиент маршрутизирует по путям
вроде `/a/liked/feed/7673…`, существующим только в браузере. Путь, который *выглядит* файлом
(`/assets/foo.js`), остаётся честным 404, а не тихо отдаёт HTML, что иначе проявляется как
`unexpected token <` в консоли.
