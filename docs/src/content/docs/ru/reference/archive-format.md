Архив — это каталог с медиа и одним подкаталогом внутри. Медиа и сайдкары каждого поста —
`.info.json`, обложки, `*_photo.json`, `*_photo.complete` — лежат сверху; всё, что ttdl записывает
*об* архиве, живёт в `.ttdl/`, и только туда этот просмотрщик за этим и смотрит. Контрактом для этих
файлов служит собственный
[справочник файлов состояния](https://ttdl.orlovsky.dev/ru/reference/state-files/) ttdl, и написано
всё здесь против него.

```
downloads/username/
  20260814_7673909736131038495_Caption.mp4          читается как пост
  20260814_7673909736131038495_Caption.info.json    его метаданные
  20260814_7673909736131038495_Caption.jpg          его обложка
  .ttdl/
    archive.txt  .all_ids.txt  missing.txt          счётчики под шапкой
    .source                                         то, что делает архив списком
    .liked.json                                     даты сохранения, когда они у ttdl есть
    loudness.json                                   усиления R128
    profile.json  avatar.jpg                        карточка автора
    .lock                                           запуск, идущий прямо сейчас
```

До появления `.ttdl/` ttdl держал всё это плоско, рядом с видео, и переносит архив на первой
изменяющей команде, которую по нему запускают. **Плоская раскладка здесь не читается.** Этот
просмотрщик никогда не пишет в архив и потому не может ничего перенести, а чтение старого места
стало бы запасным путём, который никогда нельзя было бы убрать — поэтому архив, которого ttdl не
касался со времён переноса, показывает свои посты и больше ничего: ни карточки, ни счётчиков, ни
пометки списка, пока одна команда ttdl его не перенесёт.

Формат задан только самим `ttdl.py`, и три его детали ломают наивный индексатор. Перенесены они
намеренно и закреплены в
[`tests/complete.test.ts`](https://github.com/sadorlovsky/ttdl-viewer/blob/main/tests/complete.test.ts),
который есть собственная таблица тестов `complete_ids` из ttdl, перенесённая один в один — если
правило ttdl когда-нибудь изменится, скажет об этом именно этот набор.

## Три детали

1. **Файлы одного поста не имеют общего префикса.** Медиа, `.info.json` и обложка несут в именах
   подпись, а сайдкары карусели — нет (код каруселей в ttdl обрезает префикс по
   идентификатору). Всё здесь группируется по захваченному **идентификатору поста** и
   классифицируется по суффиксу.
2. **`NAME_RE` заякорен.** Подписи регулярно содержат длинные числа, и незаякоренный поиск вытащит
   «идентификатор» прямо из подписи.
3. **Обложка карусели может быть `.jpeg`**, тогда как *изображения* карусели всегда `.jpg` — `.JPG`
   считается, `.jpeg` нет (это `PHOTO_INDEX_RE` у ttdl).

## Два намеренных расхождения

**Неполные карусели сохраняются.** ttdl их выбрасывает, потому что для ttdl «неполная» значит
«скачать ещё раз». У просмотрщика обязанность противоположная, поэтому они показываются со
`status: incomplete`, играют теми изображениями, что есть, и рисуют недостающие штрихованными
сегментами. Фильтр API по умолчанию — `status=complete`, так что они остаются по запросу, а сам
запрос — это янтарная плашка Incomplete в панели фильтров, появляющаяся только у архива, где такая
карусель действительно есть.

**Дата разрешается всегда.** `info.timestamp`, когда он есть, иначе сам идентификатор поста — его
старшие 32 бита есть секунды Unix (`post_day`). `createdAtSource` выставлен наружу,
чтобы интерфейс мог пометить выведенную дату как выведенную.

## Что читается и выбрасывается

`formats[]` и `thumbnails[]` читаются ради геометрии и затем **выбрасываются**. Это большая часть
байтов файла, и они полны живых подписанных ссылок на CDN — оставить их значило бы поместить
удалённую ссылку в один неосторожный `<img src>` от пути отрисовки.

Сам файл по-прежнему доступен дословно через
[`/posts/:postId/info`](/ru/reference/http-api/#get-apiarchivesarchiveidpostspostidinfo) для всего,
чему он нужен.

## Карточка автора

`.ttdl/profile.json` и `.ttdl/avatar.jpg`, которые `get` у ttdl пишет для архива профиля, читаются
как собственные файлы архива, а не как файлы какого-либо поста: они описывают аккаунт, а не пост, и
`parseName` их никогда не видит. Картинка к тому же единственный файл, отдаваемый из `.ttdl/`, а не
из самого архива.

Карточка — единственное в архиве, что описывает движущееся: никнейм, описание, число подписчиков, —
поэтому она едет вместе с датой, когда ttdl её снял, и шапка печатает эту дату рядом с числами.

`readCard` проверяет поле за полем, а не приводит типы: файл пишет другая программа, и прийти он
может из хранилища скопированным наполовину, а обрезанная карточка обязана выродиться в «карточки
нет», а не подставить `undefined` туда, где интерфейс зовёт `toLocaleString()`.

Картинка сопоставляется автору по хендлу, который называет карточка, а не по позиции — так что
переименованный каталог не может поставить лицо одного человека к постам другого. Она же входит в
хеш листинга, потому что заменённая картинка сохраняет имя файла, и закешированный индекс иначе
продолжал бы отдавать старую.

Аватар из буквы и оттенка по сиду рисуется *под* картинкой, так что файл, уехавший в хранилище,
откатывается к нему без дыры в вёрстке. Он же — всё, что есть для каждого автора в архиве списка: у
таких карточки нет, потому что эти посты приходят из многих аккаунтов и одного профиля, у которого
можно спросить, не существует.
